# bi-report-build：分析报告构建

交互式构建报告：先与用户充分讨论、确认计划与结构，再分步执行；每步产出先预览确认再继续；
完成后沉淀可复用 plan。**修改/整合现有报告**也走本流程（计划阶段改为差异确认，见文末）。

## 目录初始化（计划确认后立即做）

创建 `workspace/<报告名>_<报告id>/`：报告名小写英文+下划线；`<报告id>` 为随机 4 位小写字母数字，
**生成后永久不变**。目录内建 `templates/`、`history/`，并创建 `plan.md`（规范见下）。
本任务全程产物（CSV、报告）写入 `history/<run>/`（run=YYYYMMDD-HHMM，任务开始时生成一次、全程沿用）。

## 六步流程

1. **需求讨论与口径验证**：Read `references/requirements-checklist.md`，按清单与用户确认
   目标/指标/时间/范围/来源/格式；**每个列/指标先验证数据源可行性**（字段是否存在、口径、
   时间限制、筛选依赖），不可行的当场沟通替代，不带未验证的列进计划。
2. **计划与结构预览确认**：呈现执行计划 + 报告结构（章节大纲、图表类型、子报告拆分）
   + **格式约定清单**（单位/千分位/高亮/排序/合计行位置）一次列全；用户确认后才动手。
3. **采集**：按 `anta-bi` skill 执行查询；查询模板存本报告 `templates/`，CSV 存
   `history/<run>/`，`head -2` 确认表头。多品牌/多主题拆子报告并行执行（各子 agent 共用同一 run）。
   采集完给用户数据概览（行数、字段、样例）确认。
4. **加工**：按 `hamilton-report` skill 执行；DAG 存 `workspace/<报告>/analysis.py`，
   关键中间结果（聚合、趋势、异常）先给用户确认再进报告。
5. **报告生成**：结构 = 摘要/核心结论 → 关键发现（数据支撑）→ 图表 → 建议与下一步；
   格式按第 2 步确认的约定（趋势选 HTML+ECharts、结构化选 Markdown、数据密集选 Excel）；
   写入 `history/<run>/`。生成后先预览，按反馈修订至定稿。
6. **plan 沉淀**：把本次任务参数化为 `workspace/<报告>/plan.md`（规范与自检清单：
   Read `references/plan-spec.md`），告知用户下次可说「按 plan 执行，改日期为 X」复用。
   随后调 MCP `submit_feedback` 报 `report_note`：本次沉淀的口径/格式要求与任务摘要
   （context 放 skill/report/run/子报告构成）；过程中用户提出的字段口径特殊要求另报 `field_note`。

## 上下文纪律

- 每阶段最多 Read 1 个 reference；流程细节不在本文件重复的（查询/加工）去对应 skill。
- 参考数据只用于交叉核对（偏差 ±5% 以上向用户指出），结论一律以查询结果为准。

## 修改 / 整合模式

- 先 Read 现有报告与其 `workspace/<报告>/` 目录（plan.md、历史 run）；
- 第 1-2 步改为「差异范围确认」（改哪些章节、增删哪些数据），其余流程相同；
- 整合多报告时产物写入新报告目录，源报告目录只读不改。
