# 需求讨论与口径验证清单

制定计划前逐项过；关键信息缺失先问清，不盲目开工。

## 一、需求问题清单（与用户确认）

| 维度 | 要确认的 |
|---|---|
| 目标与受众 | 给谁看、支撑什么决策 |
| 关注指标 | 流水、目标达成、客流、试衣率、连带率、销存… |
| 时间范围与对比 | 环比 / 同比；周 / 月；报告期 vs 全月 |
| 品牌与范围 | 迪桑特 DESCENTE / 可隆 KOLON；区域 / 店铺层级 |
| 数据来源 | 安踏 BI（anta-bi skill）/ 本地文件 / MagicBase |
| 输出格式 | HTML（趋势）/ Markdown（结构化）/ Excel（数据密集） |

## 二、口径可行性验证（每个列/指标必须过，不臆测）

1. **字段存在性**：查 `anta-bi` skill 对应报表指引（或 Grep 根 `templates/*.reference.yaml`），
   字段名必须与 BI 逐字一致；查不到 = 不可行，找替代或砍掉。
2. **时间范围限制**：如零售日报的预算目标只能取报告期、无法取全月——先确认口径再承诺。
3. **筛选依赖**：如 DESCENTE 日报必须同时筛选 渠道品牌+商品品牌；漏筛会混入其他品牌数据。
4. **不确定的字段**：先做小范围探查验证（最小查询看返回），不允许带着未验证的列进计划。
5. **用户参考数据**：逐一评估其维度的可行性（能否查到、粒度、口径是否匹配），评估结果明确
   沟通：可直接获取 / 需调整替代 / 无法提供；不默许不可行的维度进入计划。

## 三、报告结构预览（计划确认必含）

- 章节大纲、各部分内容、图表/表格类型、子报告构成（多品牌/多主题时）
- **格式约定清单一次列全**：金额单位与千分位、百分比位数、周末/异常高亮、排序规则、合计行位置、
  同比/环比列名口径（如「预算目标」不叫「全月目标」）
- 用户确认结构+格式后才动手；调整则修订并再次确认。
