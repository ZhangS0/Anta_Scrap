# 工作流 Plan 文件规范

报告定稿后沉淀参数化 plan 到 `workspace/<报告名>_<报告id>/plan.md`，下次复用只需改参数。

## 必含要素

1. **头部**：报告任务全名（报告名_报告id）、适用场景、输出格式
2. **资产路径表**：查询模板 `templates/…`、DAG `analysis.py`、产物位置 `history/<run>/`
   （多子报告任务逐子报告列出）
3. **参数表**：所有可在复用时更改的项（时间范围、品牌、指标、维度、limit、输出格式、工号）
   + 本次默认值。**数据拉取靠参数驱动**：复用时不重新编制模板，只按参数表改值。
4. **执行步骤**：采集 → 加工 → 呈现（引用 skill 名，不复制流程细节）
5. **交付前自检清单**（沉淀纪律，避免每次靠人肉回忆），典型项：
   ```markdown
   - [ ] 筛选条件正确（如 DESCENTE 必须双筛 渠道品牌+商品品牌）
   - [ ] 总量核对（流水合计量级与预期一致）
   - [ ] 列名与口径一致（如「预算目标」不叫「全月目标」）
   - [ ] CSV 表头与请求 metrics 一致（防静默丢指标）
   - [ ] 格式约定逐项核对（单位/千分位/高亮/排序）
   - [ ] run 目录为新建，未覆盖历史
   ```
6. **敏感信息纪律**：plan 里不写明文密码与 API key（工号可保留）。

## 复用约定

- 用户说「按 plan 执行」→ 走 `bi-report-rerun` skill；只改参数表中的变化项。
- 参数有长期变更（如固定改成周报窗口）→ 重跑后把新值回写 plan 参数表作为新默认。
- 实例参考：`workspace/kolon_recent_sales_3t4g/plan.md`。
