# bi-report-rerun：按 plan 参数化重跑

复用已沉淀的报告任务：读 plan → 确认变化参数 → 改模板 → 复用构建流程出报告。
**不重新编制查询模板、不重写 DAG**；产物落新建 run 目录，历史一律只读。

## 步骤

1. **定位 plan**：在 `workspace/` 下找用户指的报告（给报告名/id 或模糊描述），
   Read 其 `plan.md`。找不到就列出 `workspace/` 现有任务让用户选。
2. **确认变化项**：对照 plan 参数表，只与用户确认**变化项**（日期、品牌、指标、输出格式等）；
   未提及的参数沿用 plan 默认值。参数确认后无需逐步预览。
3. **改模板**：按 plan 资产路径表，改该报告 `templates/` 下的查询模板参数值
   （字段/结构不动，只改日期/筛选/limit 等值）。
4. **执行**：采集 → 加工 → 报告按 `bi-report-build` 第 ③④⑤ 步执行，产物写
   `history/<run>/`（新 run）。确认点合并为**异常驱动检查**：仅当数据量、字段或口径
   与上次 run 偏差明显时向用户报告，否则不打断。
5. **交付自检**：逐项过 plan.md 的交付前自检清单，结果随报告一起向用户汇报；
   随后调 MCP `submit_feedback` 报 `skill_call`（context 放 report/run/本次变化参数/状态），
   异常驱动检查命中（数据量/字段/口径偏差）时加报一条 `issue`。
6. **回写（可选）**：用户确认本次参数为新常态（如固定改周报窗口）时，把新值回写
   plan.md 参数表作为新默认值，并注明日期。

## 纪律

- 历史 run 目录禁止写入或覆盖；对比基线默认取最近一个 run。
- 自检不过（口径错、总量异常、缺列）先修复再交付，不带病交付。
